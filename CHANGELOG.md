# Changelog

All notable changes are listed here, newest first. Versions stay below 1.0 until the v1.0 criteria of `docs/ROADMAP.md` hold; P0 produces no release, so everything so far is unreleased.

## Unreleased

- Flight recorder: `perf.jsonl` now has resident memory on macOS and Windows too (#90): the new `os` crate `crastu-procmem` reads it with `task_info` and `GetProcessMemoryInfo` (`unsafe` in one commented module), and the CLI and the desktop app register it with `crastu_recorder::set_resident_reader`.
- Flight recorder, slice 3 (part of #25): `crastu host` writes `perf.jsonl` once a second (queue depth, the timings of jobs that finished, resident memory on Linux and Android; macOS and Windows follow in the next entry, because reading it there needs `unsafe`), and the desktop window now has its own recorder (session folder for `crastu-desktop`, panic hook, crash handler, `end.json`) with frame time p50, p99 and max per second. Settings > About shows the version, the system and the log folder, with Open logs (opens the folder in the file manager) and Copy diagnostics (a redacted, bounded text with the version, system, modules, the last events and how the previous run ended; nothing is sent). The frame-time numbers and the macOS Open logs button need a hands-on check.
- Settings, Models and licences (part of #86): lists the catalogue with the licence badge (`Conditional` shows the licence's note), the state of each model and a total of what is installed; Download (resumes an earlier `.part`), Cancel and Remove (behind a confirmation) work from the page. Downloads run on a background thread through the shared Offline gate with progress, cancel and errors as toasts; with Offline on, Download is disabled ("Offline is on"), a running download is cancelled and installed models stay usable. Remove only touches the catalogue's file, its `.part` and the empty `.part.lock` in the models folder. New crates `crastu-models-model` (plain data) and `crastu-models-ui`. Real downloads still need a hands-on check on a Mac.
- Audio capture, slice 1 (part of #85): `crastu-audio` gets an `AudioSource` trait with a `SyntheticSource` and a cpal `MicSource` behind the off-by-default `mic` feature (default device or by name, permission errors as `Denied`/`Unknown`), a converter to 16 kHz 20 ms frames (downmix, windowed-sinc resampler; rates outside 1..=384000 Hz are errors) with peak/RMS `Level` and clipping flag, a non-blocking SPSC ring buffer counting `dropped_frames`, and a `VoiceGate` trait with an energy gate (hysteresis, hangover). Tests need no hardware; the live microphone is checked by hand with `cargo run -p crastu-audio --example level --features mic`. The WAV `FileSource` (PCM and float, bounds-checked, 256 MiB cap) is the new crate `crastu-audio-wav`, split off to keep both crates under the size limit.
- Flight recorder, slice 2 (part of #25): `crastu-crash` writes `crash.txt` into the session folder when the CLI or host dies from SIGSEGV, SIGBUS, SIGILL, SIGFPE or SIGABRT (signal, `si_code`, fault address, pid, session id, time; fixed fields only), from an async-signal-safe handler with its own alternate signal stack, then chains to the previous handler and re-raises so the process still dies by the signal and the system's crash report still happens. Stack overflows are reported too, and std's "has overflowed its stack" message and abort still follow. It is the only crate on the crash path that allows `unsafe` (one commented module). Unix only; Windows and the desktop window process (no recorder there yet) come later.
- MCP: agent tokens are not stored in the Keychain for lookup by agent name (decision 25 update): a lookup by name would let any process of the same user act as that agent. Tokens stay in the client's `env` block.
- Offline mode, slice 3 (part of #22): `crastu host` (and the desktop binary's `host` command) gives its host a real gate, built by the same code as `crastu models` (`CRASTU_OFFLINE` wins, else `network.offline` in `settings.json` in the shared data folder), so a request a tool call refuses is logged in the activity log by what and host. The host reads the setting again before every tool call, so a change the desktop saves acts on a running host at its next tool call (work already running keeps the value it read; a change the desktop could not save, or a desktop locked by its own `CRASTU_OFFLINE`, does not reach a host started without it); `CRASTU_OFFLINE`, when set, decides for the whole run. When the setting cannot be read the host keeps running with Offline ON and says so once on stderr; without a data folder the host does not start (`models` still stops with an error). No built-in host tool makes a network request today.
- Offline mode, slice 2 (part of #22): the desktop app builds its gate at start and is Offline ON when `settings.json` cannot be read; Settings > Privacy has an Offline switch (saved as `network.offline`, applied at once, disabled with a note while `CRASTU_OFFLINE` is set) and the palette has "Turn Offline on/off"; the switch fails closed (an unreadable `settings.json` keeps Offline on and is never overwritten, a failed save rolls back a change toward off, the palette hides the Offline commands while `CRASTU_OFFLINE` decides); `Host::set_net_gate` and `Host::record_refusals` log refused requests (what and host only) in the activity log.
- Settings, Agents (MCP) (slice 2 of #15): pair an agent by name, see its token once with Copy and a note to put it in the client's `env` block as `CRASTU_AGENT_TOKEN` (not on the command line), rotate, revoke (behind a confirmation), set the default policy per call class and a per-agent override, and read the newest calls. The approval policy now lives in the host database (`agent_policy`, migration 3) and the host reads it on every call, so a change acts at once and survives a restart; a policy that cannot be read, or holds a row it does not understand, lets only reads through; the policy is written in one transaction. A damaged policy no longer hides the agent list: a banner says the host allows reads only, with Reset policy to defaults behind a confirmation (one transaction, and only while the policy is still damaged, so a stale confirmation never wipes a healthy one; a failed COMMIT is rolled back); while it is damaged the policy controls are disabled and policy changes are refused. Auto for Changes or Deletions (the defaults) and for one agent's Deletions asks first, since a default also covers callers without a token. Pair and Rotate are disabled while the token box is open and the focus moves to it. A caller's declared name is cleaned (control and bidi characters dropped, 64 characters) before it is shown. An existing data folder or database that is looser than 0700/0600 is tightened on open.
- UI: `surface()` takes the YCbCr matrix and range per buffer (BT.601, BT.709, BT.2020; `420f` and `420v`), read from the `CVPixelBuffer`'s colour tag, through a small patched copy of `gpui-pre-apple` under `vendor/` (`docs/vendor-gpui.md`); `cargo xtask colour-report` and `cargo test -p xtask-colour` measure a BT.709 chart (worst CIEDE2000 8.00 before, 0.41 after, limit 1.0), and `cargo xtask licences` lists vendored copies. Part of #39 (upstream proposal not filed yet, the media layer must tag its buffers).
- UI: the rail and the Settings entry show their icons (original 24x24 SVGs, 1.8 px stroke, `currentColor`) beside the label; embedded in `crastu-ui` and served to GPUI through an asset source; `icon` size and stroke tokens (part of #7).
- Build: decision 32 keeps `runtime_shaders` for CI and release builds (no Metal Toolchain needed); precompiled shaders wait for a start-up measurement (#42).
- ML: `crastu-ml` session registry (slice 1 of #26): one session per model and options per process, counted handles, idle expiry on an injectable clock, stats snapshot; no runtime dependency yet.
- MCP: agents can be paired with a token (`crastu agents add|list|revoke|rotate`, `CRASTU_AGENT_TOKEN` in the shim); per-agent policy overrides apply only to paired agents and the activity log marks unpaired calls.
- Foundation: workspace and layering checks, core crates, headless host with the stdio MCP shim and approval policy, `crastu-app` view models.
- UI: GPUI pinned and bundled fonts (Inter, JetBrains Mono), design tokens with a lint against literals, base controls with every state, badges, tooltip, toast and dialog, a component gallery.
- Shell: Cmd/Ctrl+K command palette (go to a module or a Settings category, toggle panels, switch theme, font and density); window frame with rail, sidebars and inspector, Appearance settings that persist, onboarding screens with real macOS permission checks (hands-on test open).
- Spikes: one shared ONNX Runtime (decision 28), video preview through VideoToolbox into `surface()` (decision 27).
- Licences: `cargo xtask licences` writes NOTICE and LICENSES/ for the shipped dependency graph and the bundled fonts, and `--check` runs in CI.
- Models: catalogue entries (Whisper Small, Silero VAD, YuNet) with pinned sha256 and size, a resumable verified downloader with an https adapter, `crastu models list|download`, and onboarding that reads its model table from the catalogue.
- Offline mode: one gate in `crastu-core` that network requests pass through, the `network.offline` setting and `CRASTU_OFFLINE`, model downloads refused by name while it is on (installed models keep working), and `crastu models list` showing the state. The desktop app and the CLI now share one data folder lookup; on Windows it is `%APPDATA%\Crastu` (pre-1.0, no migration), and the `crastu-ipc` socket path still follows its own rules.
- Flight recorder (part of #25): `crastu-recorder` keeps a local session folder per run (`session.json`, `events.jsonl` flushed per line, `perf.jsonl` schema, `panic.txt` from a panic hook, `end.json` on a clean exit) under `CRASTU_LOG_DIR` or `~/Library/Logs/Crastu`, keeps the newest 20 sessions and 50 MB (a running session is protected by an OS lock and never deleted; a live session's files are size-capped), and is wired into `crastu-cli` (`host`, `mcp`, `models`). The crash-signal handler and Settings, About "Open logs" and "Copy diagnostics" follow in later slices.
- Build: the minimum Rust version is 1.89 (`File::try_lock`, used for the model download lock).
