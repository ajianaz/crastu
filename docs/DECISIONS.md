| 25 | 2026-11-11 | MCP agent names are self-declared labels for now; processes of the same OS user are trusted. Token pairing per agent comes in P1 (#15) before per-agent overrides can be set in Settings. Update 2026-11-12 (#15, slice 1): enforced in the host. `crastu agents add NAME` issues a token (`crastu_` plus 32 random bytes as hex) that is shown once; the host keeps only its SHA-256 hash, in the `agents` table of `crastu.db`. The shim sends the token from the environment variable `CRASTU_AGENT_TOKEN` (never an argument) with every call and the host resolves it to the agent, ignoring the declared name. Per-agent overrides apply only to paired agents; an unpaired caller always gets the defaults and the activity log marks it as unpaired. A token that is presented but unknown, rotated or revoked is an error, never a silent downgrade. `agents revoke` and `agents rotate` act on the next call. The user keeps the plain token in the MCP client's configuration; Keychain storage and the Settings, Agents screen are the next slices. |
| 26 | 2026-11-11 | Desktop first: the GPUI app on macOS (then Windows) is the only front end in the plan. A web front end comes last, after every other platform, because dictation needs the microphone, global hotkeys and paste into other apps, which a browser cannot provide. If built, it is a remote front end over the host and `crastu-app` state (HTTP or WebSocket), not a WebAssembly port of the GPUI UI; no React layer on top of or under GPUI. Reasons: GPUI on the web is a showcase-only target today (one canvas, no screen-reader semantics), and React-over-GPUI bindings are early and would add a JavaScript runtime to the app. |
| 27 | 2026-11-11 | Video preview v1 on macOS: VideoToolbox hardware decode straight into GPUI `surface()` (no copy, `420f` output). Fallback when VideoToolbox cannot decode a stream: software decode into a pooled `CVPixelBuffer` at preview size. `img()` is the Windows path, decoding at preview size. The playback clock lives with the decoder or audio output, never in `render()`. The BT.709 colour matrix and 60 fps with `surface()` are fixed before P4. Evidence: `docs/spikes/gpui-video.md`. |
| 28 | 2026-11-11 | One ONNX Runtime per process on macOS: sherpa-onnx is built with its `shared` feature and `libonnxruntime.dylib` (from its release archive, 1.28.2 today) sits next to the executable, in the app bundle's `Contents/MacOS`. sherpa-onnx finds it through the application's own rpath (`@executable_path`), and uteke finds it because it looks in the executable's folder when `ORT_LIB_PATH` is not set, so no environment variable is needed. Where a variable is needed (tests, another layout) it is set on a spawned child process with `Command::env`, never with `std::env::set_var`, which is `unsafe` in edition 2024 and denied in the workspace. The static layout stays a working fallback. CI builds from a pinned, checksummed archive, and a runtime upgrade is retested with uteke's tests. Evidence: `docs/spikes/onnx-runtime.md`. |
| 29 | 2026-11-11 | Fonts ship with the app and are never taken from the system: Inter 4.1 (Regular, Medium, SemiBold) and JetBrains Mono 2.304 (Regular, Medium), the default pairing, are bundled in `crastu-ui/assets/fonts` and registered at start-up (SIL Open Font Licence 1.1, the licence text beside each family, source and checksums in the README there). Space Grotesk and IBM Plex Sans and Mono are bundled too (all three pairings); a family that is still missing falls back to a system font. Reason: GPUI draws no glyph for a family it cannot find, and the design is only reproducible with its own fonts. Static files are used because GPUI's weight handling of variable fonts is untested. |
| 30 | 2026-11-12 | Offline mode has one gate: `NetGate` in `crastu-core` (no I/O, cheap to clone, shared flag). Every outbound request type (model download, update check, provider call, sync) must call `gate.check(what, url)` before it opens a socket; with Offline on it returns an error that names what and which host (never path, query or credentials) and the gate keeps a bounded list of refusals for the activity log. The switch is the setting `network.offline` (off by default) and the environment variable `CRASTU_OFFLINE` (`1`, `true`, `yes`, `on` and `0`, `false`, `no`, `off`, any case); a recognised environment value wins over the setting, anything else leaves the setting in charge, and a setting that cannot be read counts as on. Models already on disk keep working; a missing one says how to get it. Slice 1 covers the gate, the setting, the downloader (`GatedFetch`) and the CLI; slice 2 adds the Settings switch in the UI and the MCP activity-log record of refusals, and each later network feature wires its own requests through the gate. |
